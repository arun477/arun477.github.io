# arun477.github.io

Personal site, live at https://arun477.github.io/. Hugo, no theme, minimal JavaScript (theme toggle, plus the hive banner on About).

## Layout

- `content/posts/` — one Markdown file per post (writing, projects and tools all live here). Old `/utilities/` URLs redirect via `aliases`. Front matter is only `title`, `date`, optional `description`, `tags`.
- `content/_index.md` — home page: Arun's `role` and `links`, plus fields a home agent manages (`note`, `pins`, `hide`, `shown`, `step`, `lastmod`; checked by `layouts/_partials/home/params.html`). Rules for that agent: `docs/home-agent.md`. Keep `date` set: without it Hugo dates the home page from `lastmod`, and a future `lastmod` would unpublish it.
- `content/news/` — the Feed (served at `/feed/`; `/news/` redirects): tech news and engineering blog posts, published daily by an outside agent. One `YYYY-MM-DD.md` per day with an `items` list in front matter; each item has a `kind` (news, blog, paper, release; list in `layouts/_partials/news/kinds.html`). The folder keeps the name `news` because the agent writes there. Schema and rules for that agent: `docs/feed-agent.md` (keep it in step with the templates). Templates: `layouts/news/` (`section.html`, `page.html`, `page.md`, `section.json`) and `layouts/_partials/news/`; `items.html` validates each item and fails the build on a bad one. Each kind also has its own paged list at `/feed/<kind>/` (section pages added by `content/news/_content.gotmpl`, rendered by `layouts/news/section.html` with `.Params.kind`); the kind bar on `/feed/` and those lists is links (`_partials/news/kind-links.html`), so a choice holds across pages and the page count is the kind's own. Day pages keep a CSS-only filter (radio buttons + `:has`, `_partials/news/filter.html`); its rules sit in `assets/css/feed.css`. Feed templates read days from `.RegularPages`, never `.Pages`, so the kind sections never count as days. The Feed is the one exception to the front-matter rule above, stays out of the main RSS feed (own feed at `/feed/index.xml`) and gets its own block on the home page.
- `content/themes/` — Themes (`/themes/`): the Feed synthesized into ranked storylines by an outside agent. One front-matter-only snapshot `YYYY-MM-DD.md` per update; only the newest counts. `_content.gotmpl` turns each of its themes into a page at `/themes/<slug>/`; `/themes/` paginates them. Snapshots are `build.list: local`, so they never reach Latest, RSS or llms.txt. Rules for that agent: `docs/themes-agent.md`. Templates: `layouts/themes/`, `layouts/_partials/themes/` (`themes.html` validates and fails the build on a bad snapshot).
- `content/changelog.md` — `/changelog/`: what changed, newest first, for agents that publish to or read the site. Unlisted (no nav, home, RSS or sitemap); linked only from the footer and `/llms.txt`. Add an entry whenever URLs, schemas, data files or publishing rules change.
- `layouts/` — the whole theme: `baseof.html` (head, header, footer, the one stylesheet), `home.html`, `section.html`, `page.html`, `taxonomy.html`, `term.html`, `404.html`, plus `news/` for the Feed and `themes/` for Themes. Ornaments are SVG partials in `layouts/_partials/ornament/`: `defs.html` (the one hidden sprite, included once by `baseof.html`: the leaves `#lf-ginkgo` (a fan, not a heart), `#lf-momiji`, `#lf-yanagi`, and the row glyphs `#ic-<name>`), `enso.html` (dict `size` px default 190, `leaves` default 34 and at least 30, `seed`, `sun` default true, `falling` default true, `draw` default false, `class`; one brush stroke of leaves along the tangent, heavy at the start and tapering by leaf size, the ink centred in its box; layout computed at build time, call with `partialCached`), `seal.html` (dict `text` default "AA", `size` px default 34, `class`), `brush.html` (dict `kind` "under" or "vertical", `length` px, `class`), `fuji.html` (footer scene), `crest.html` (header logo; takes a px size), `rnd.html` (helper).
- Agent/crawler outputs, all generated: `layouts/robots.txt` (allow all + sitemap), `layouts/home.llms.txt` (`/llms.txt` index), `layouts/page.md` (every post also at `<url>/index.md`), `layouts/rss.xml` (full-content feed), `layouts/_partials/jsonld.html` (Person / BlogPosting JSON-LD). New posts appear in all of them automatically.
- `assets/css/` — the stylesheet, in partials concatenated by `baseof.html` (`resources.Concat`, minified, fingerprinted) in this order: `base.css` (fonts, tokens, reset, type, header, footer, shared rows, glyphs, chips, buttons, ornaments, motion), then `home.css`, `posts.css` (post lists, post page, tags, 404), `feed.css`, `themes.css`, `about.css`. Shared rules go in `base.css`; a page's own rules go in its partial only. A new partial must be added to the list in `baseof.html`.
- `assets/images/` — images, referenced as `/images/x.png`; processed at build time. `static/audio/` — audio files.

## Writing

- Publish a post: add `content/posts/<slug>.md` and push to `main`. That is the whole process.
- Section order (nav and home) follows `weight` in each section's `_index.md`: Posts 1, Themes 2, Feed 3 (synthesis before the raw stream).
- New section (e.g. `notes`): create `content/notes/_index.md` with a `title`. Nav and home page pick it up automatically; no template changes.
- Unpublish without deleting: add `draft: true` to front matter.
- Display math: `$$ ... $$` on its own lines. It is rendered to MathML at build time; inline `$` math is not enabled.
- Raw HTML is allowed in Markdown (e.g. `<audio controls src="/audio/x.wav"></audio>`).
- Images: drop the file in `assets/images/` and write `![alt](/images/x.png "optional caption")` on its own line. `layouts/_markup/render-image.html` handles the rest: full-column width, resize above 1600px, width/height attributes, and a matte sampled from the image's left edge so tall images never show grey bars. A missing image fails the build. Don't use the `figure` shortcode or raw `<img>`.

## Design rules

Japanese, restrained, like an antique naturalist print on washi: calm space, strict alignment, sharp edges, ornament used once or twice per page and never as wallpaper. All text is English (no Japanese words or kanji). One column, `--wrap` (60rem) wide with `--gutter` side padding (`main` and `.in`); reading text inside it is held to `--measure` (42rem). Header and footer are full-width bars whose contents align to that column; `.bleed` takes a band inside `main` to the viewport edges.

- Edges: zero border-radius everywhere (enforced globally in `assets/css/base.css`). Circles (ensō, sun, crest) are drawn in SVG, never with border-radius. Hairline rules, not boxes.
- Alignment and spacing: every element, rule and fill starts and ends on the column edges. Every margin, padding and gap uses the spacing scale `--s1`..`--s9` (4, 8, 12, 16, 24, 32, 48, 64, 96px); tap targets are at least `--tap` (44px): small links and chips keep their look and get an invisible hit area (`::before`, or `min-height` with negative margins) instead. The header is `--bar` (64px). `main` starts `--s6` below the header (`--s5` on phones); a page that opens on a band pulls it up with `margin-top: calc(-1 * var(--s6))`. Phones (under 40rem): `--gutter` is 16px, no horizontal scroll at 360px; the gutters never go inside a notch's safe area (`viewport-fit=cover` plus `max(var(--gutter), env(safe-area-inset-*))`). `.bleed` spans the body's width (a container query unit), so it ends with the header and footer bars, not under the scrollbar.
- Type: Shippori Mincho B1 (`--mincho`; 400/500/600/700) for headings, reading text and titles; Zen Kaku Gothic New (`--gothic`; 400/500/700) in uppercase wide tracking (`--track-ui`, `--track-wide`) for UI (header, footer, labels, meta, chips, buttons); system mono (`--mono`) for dates and code. A tracked label in a box (button, chip, filter label) gives back its trailing letter-spacing (`text-indent` or a smaller right padding) so it sits in the true centre. Both fonts are self-hosted latin subsets in `static/fonts/` with their unicode-range; `baseof.html` preloads Mincho 400 and Gothic 500. Sizes come from the type scale `--t-ui-sm`, `--t-ui`, `--t-sm`, `--t-body`, `--t-read`, `--t-lg`, `--t-xl`, `--t-2xl`, `--t-3xl`.
- Dates: one family. Heads and day labels: "17 October 2026". Meta lines, buttons and chips: "17 Oct 2026". Vertical row dates: "17 Oct" this year, "Mar 2025" for older years. Times: "17:08 UTC".
- Home: no hero (the site title is a screen-reader-only h1). It opens on a compact top band (`home.html`, `home.css`): the leaf ensō (168px, draws in once) with the AA seal, then one label line ("Managed by agents" with a static REC square, and the date of `lastmod`), the agent's `note` between red corner marks (a default line when it is empty), and two equal ghost buttons, "Today's Feed" and "Themes". No seigaiha strip under it: the stream's ink rule divides them. The stream sits beside a vertical Mincho "Latest" heading with a vertical brush rule (horizontal with a short brush on phones). About (`content/about.md`, layout `layouts/about.html`, in the nav): role kicker, name with a brush underline, the bio from the page body, a compact row of social links (role and links from `content/_index.md` front matter), the AA seal on the name's line (no ensō); "Run by agents" (one row per part and who runs it, from `runs`, then the `oversight` line between corner marks), then the hive (`assets/hive.js`, loaded on About only) as a banner on the column edges. The hive is drawn flat and sharp in the leaf palette (paper sheets with hairline rules, no shadows, no rounded strips): five agent bees take a request, brief, work together face to face, deliver, remember and dream in a 36s loop; pauses off-screen, shows a still frame under reduced motion, `?hive=<seconds>` freezes a moment for checking.
- Home is one stream (`_partials/latest.html`): posts, every Feed item and the current themes together, newest first, in the row style with each section's own glyph and its full summary. Pinned rows come first. The first `shown` rows show; each "Show more" (nested details elements, a ghost button) opens the next `step`; after four batches it links to the section pages, so the page size is bounded. No separate section blocks.
- Section pages (Posts, Themes, Tags) open with one slim `.sechead` line: title, date, chips. No intro paragraph: the description lives in the meta tags only. Post rows (`_partials/list.html`, on Posts and tag pages) show each post's `description` under the title, clamped to two lines.
- Feed (`layouts/news/`, `feed.css`): a masthead (`.fd-head`: the newest day's date, a 48px "The Feed" over a brush stroke, the newest day's headline as its summary, the updated time and RSS / JSON chips), the kind filter between a double rule and a single one, the lead story (the newest spike, set large, with a TOP seal at its top right; no ensō), then each day (a date label, its headline and brief; the first day on page 1 shows only the brief, since the masthead carries its headline) with its items in a two-column grid (`.fd-grid`, a hairline on the column centre). Day pages use the same masthead stacked (`.fd-head.is-day`: Feed back-link, date, the headline as h1, the brief). Feed and Themes pages end on `.fd-nav`: two equal ghost buttons with a maple leaf (and "Page 2 of 3") between; newer on the left, older (the next page) on the right, on list and day pages alike.
- Post page (`page.html`, `posts.css`): a compact head (glyph, kind, date, read time, the title with a brush underline, the description) beside a small hanging scroll (dark rods, a sprig of 2 to 4 leaves of one kind chosen from the post's file name, the first tag (short tags stacked upright), the AA seal). The body is held to `--measure`; figures, code and rules reach the column edge below 60rem. h2 is a plain Mincho heading under a short ink hairline (no leaf), no drop cap, ordered-list numbers muted. Contents sit beside the body on wide screens and fold into a "Contents" row (a details element, "Show"/"Hide" in words) on narrower ones.
- Header (about 64px, sticky; it scrolls away on short landscape screens): the leaf crest (an ochre ginkgo fan in a fine ink circle) with the name in Mincho and the role in small uppercase Gothic; nav in uppercase Gothic, the current page marked by a red brush-stroke underline, hover draws an ink brush stroke; theme toggle. Under 44rem the nav folds behind a two-rule menu button (CSS-only checkbox; a `pageshow` handler unticks it when a page comes back from the back/forward cache) and opens as a full-width panel of 14px rows; the theme toggle stays visible. Footer: line-drawn Mount Fuji (concave slopes, snow cap, red sun, two birds, low hills joined to its slopes and running to the column edges) sitting on a slate seigaiha band (the tile anchored on the centre), then the slate bar with the copyright, the social links from `content/_index.md`, RSS and Changelog (short links get a 44px-wide hit area; the focus ring turns light on slate).
- Colour: tokens at the top of `assets/css/base.css`: `--ground` (washi), `--paper`, `--mist`, `--mist-2`, `--ink` (sumi), `--muted` (light `#6a5e51`: at least 4.5:1 on ground and mist), `--rule`, `--red` (seal red), `--on-red`, `--slate`, `--slate-2`, `--on-slate`, `--vein`, plus the fixed leaf palette `--leaf-ochre(-2,-3)`, `--leaf-rust(-2,-3)`, `--leaf-teal`, `--leaf-olive`. Dark tokens appear twice (system preference and `[data-theme="dark"]`); change both. The old names (`--bg`, `--text`, `--card`, `--line`, `--hover`, `--accent`, `--serif`, `--sans`) remain as aliases for `assets/hive.js`; new rules use the new names.
- Glyphs (`layouts/_partials/icon.html`, 24 viewBox, 1.3 stroke, square caps, drawn at 24px in a 44px box) name content types, never actions (no arrows, pencils, tags, +/- marks): hanging-scroll page with a cord = post, calendar page with two ring posts = Feed day, broadsheet = news, stab-bound notebook = blog, folded document with a seal = paper, bundle tied in cloth (furoshiki) = release, brush sparkline over a baseline = theme trend (rising is red, steady, fading). The drawings are symbols in the `ornament/defs.html` sprite; `icon.html` emits a `<use>`, so CSS reaches them only through their own classes (`g-f` fill, `g-t` trend line, `g-hot` red via `var(--hot)`) and inherited colour.
- Rows: one grammar everywhere (`.feed` in `base.css`): `ol.feed > li.post > a >` an optional vertical mono date (`time.vd`, 11px), the seal-outline glyph box (`.av`, red outline; `li.spike` fills it red, `li.pin` outlines it in ink, `.steady`/`.fading` mute it; date and box start on the meta line's cap height), then `.b` with the meta line (`.m`, uppercase Gothic), the Mincho title (`strong`, the full column) and, on section and detail pages only, the muted summary (`.s`, at most 62ch). No index numbers, ranks or counts on rows or labels: the lists change daily, so a number means nothing; order carries rank. Themes index groups rows under Rising / Steady / Fading.
- Accent is seal red, used only for seals, signals (the static REC marker, spike, rising theme, reading progress, waveform playhead), brush marks, corner marks and the current-nav underline; never for running text. Links stay ink with a red underline offset below the text. Motifs (sparingly): the leaf ensō with a red sun (home top band and 404 only), the AA name seal (rotated -4deg, kept inside its box), the post scroll's leaf sprig, red corner quote marks (`.corners`, one inset everywhere), brush strokes, the seigaiha band (footer only), the hanging-scroll panel on posts. No mist bands, decorative strips or long rounded bar strips.
- Row hovers stay exactly within the column rules; a brush rule draws along the row's bottom edge and content slides inward (transform) instead of anything bleeding outward. `.b` carries a right padding equal to the slide, so hovered text lands on the column edge, not past it. The Feed grid does not slide.
- JS is limited to the theme toggle (inline in `baseof.html`, with the one-line `pageshow` handler that closes the phone menu) and `assets/hive.js` on the About page. The bee characters, palette and choreography live in that one file.
- Motion is CSS-only except the hive banner: a short cross-fade between pages (view transitions, header held still); the home ensō may draw in once (`draw`: leaves fade and settle in stroke order, about 1s, no layout shift) and its two loose leaves drift very slowly; a brush rule drawn under hovered rows and nav links (no fill or colour inversion; hover is mouse-only, touch gets the rule on tap); scroll-driven progress bar. The REC marker does not blink. No entrance animation on list rows or main and no per-title morph: inside the view transition they made rows pop in one by one and titles stretch. All disabled under `prefers-reduced-motion`.

## Build and deploy

- Hugo version is pinned in `scripts/install-hugo.sh` (and `HUGO_VERSION` in `netlify.toml`; change both) (cloud sessions run it on start; on macOS use `brew install hugo`).
- Check: `hugo` must build with no ERROR or WARN lines. Preview: `hugo server`.
- Deploy: push to `main`. `.github/workflows/deploy.yml` builds and force-pushes `public/` to the `gh-pages` branch, which GitHub Pages serves. Pull requests build but do not deploy; Netlify builds a preview of each from `netlify.toml`.
- Never commit `public/` or edit the `gh-pages` branch by hand; everything served must come from this source.
